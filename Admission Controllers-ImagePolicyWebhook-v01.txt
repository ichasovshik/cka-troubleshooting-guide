# Kubernetes CKA Lab: Admission Controllers — ImagePolicyWebhook

## Overview
This document contains the complete configuration, lab steps, and questions for the **Admission Controllers** lab focusing on the `ImagePolicyWebhook` admission plugin.

---

## Lab Questions & Task Breakdown

### Question 1 of 8: Introduction
* **Context**: The `ImagePolicyWebhook` admission controller intercepts pod creation requests and consults an external webhook service to determine whether the container images specified in the pod spec should be allowed or denied.
* **Webhook Endpoint**: `https://image-checker-webhook.default.svc:1323/image_policy`
* **Configuration Directory**: `/etc/kubernetes/imgvalidation`

### Question 2 of 8: Primary Purpose
* **Question**: What is the primary purpose of the `ImagePolicyWebhook` admission controller?
* **Options**:
  * Encrypt container images at rest in the container registry
  * Automatically scan images for vulnerabilities after pods are deployed
  * **Validate container images against an external webhook before allowing pod creation** *(Correct Answer)*
  * Authenticate users trying to pull container images

### Question 3 of 8: Examine Incomplete Configuration
* **Directory**: `/etc/kubernetes/imgvalidation/`
* **Files Present**:
  1. `admission-configuration.yaml` — The `AdmissionConfiguration` resource that references the `ImagePolicyWebhook` config (incomplete).
  2. `imagepolicy-conf.yaml` — The `ImagePolicyWebhook` plugin configuration (incomplete).
  3. `kubeconf.yaml` — The kubeconfig file used by the API server to connect to the webhook (incomplete).
  4. `webhook.crt` — The TLS certificate for the webhook server.
* **Inspection Commands**:
  ```bash
  cd /etc/kubernetes/imgvalidation
  ls -la

```

### Question 4 of 8: `defaultAllow` Meaning

* **Question**: In the `ImagePolicyWebhook` configuration, the `defaultAllow` field is currently set to `true`. What does this mean when the webhook backend is unavailable?
* **Options**:
* **All pod creation requests are allowed (fail-open)** *(Correct Answer)*
* Only pods in the default namespace are allowed
* The API server retries indefinitely until the backend responds
* All pod creation requests are denied (fail-closed)



### Question 5 of 8: Task - Configure Fail-Closed

* **Task**: Reconfigure the `ImagePolicyWebhook` to reject images when the webhook backend is unavailable (`fail-closed`). Change `defaultAllow: true` to `defaultAllow: false` in `imagepolicy-conf.yaml`.

### Question 6 of 8: Task - Configure Kubeconfig Endpoint

* **Task**: Update the `server` field under `clusters[0].cluster` in `/etc/kubernetes/imgvalidation/kubeconf.yaml` to point to the image scanner webhook endpoint:
`https://image-checker-webhook.default.svc:1323/image_policy`

### Question 7 of 8: Task - Enable Admission Plugin on API Server

* **Task**: Reconfigure the API server manifest (`/etc/kubernetes/manifests/kube-apiserver.yaml`) to:
* Enable the `ImagePolicyWebhook` admission plugin.
* Set `--admission-control-config-file=/etc/kubernetes/imgvalidation/admission-configuration.yaml`.
* Mount the `/etc/kubernetes/imgvalidation` directory as a volume inside the static pod.



### Question 8 of 8: Task - Verify and Test Deployment

* **Task**: Deploy the test resource defined in `~/test-deploy.yaml` to verify that the `ImagePolicyWebhook` is working correctly.
* **Expected Result**: The pod should be **denied** by the webhook because the image violates the image policy.
* **Command**:
```bash
kubectl apply -f ~/test-deploy.yaml

```

## Lab Configuration Files

### 1. Admission Configuration (`admission-configuration.yaml`)

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: AdmissionConfiguration
plugins:
- name: ImagePolicyWebhook
  path: /etc/kubernetes/imgvalidation/imagepolicy-conf.yaml

```

### 2. Image Policy Configuration (`imagepolicy-conf.yaml`)

```yaml
imagePolicy:
  kubeConfigFile: /etc/kubernetes/imgvalidation/kubeconf.yaml
  allowTTL: 50
  denyTTL: 50
  retryBackoff: 500
  defaultAllow: true

```

### 3. Webhook Kubeconfig (`kubeconf.yaml`)

```yaml
apiVersion: v1
kind: Config
clusters:
- cluster:
    certificate-authority: /etc/kubernetes/imgvalidation/webhook.crt
    server: [https://placeholder.example.com](https://placeholder.example.com)
  name: checker_webhook
contexts:
- context:
    cluster: checker_webhook
    user: api-server
  name: checker_validator
current-context: checker_validator
preferences: {}
users:
- name: api-server
  user:
    client-certificate: /etc/kubernetes/pki/front-proxy-client.crt
    client-key: /etc/kubernetes/pki/front-proxy-client.key

```
